# Аудит Telegram Mini App и мультиплеера — 7 октября 2026

## Проверенные сценарии

| Сценарий | Итог |
| --- | --- |
| Запуск из Telegram и вход | Официальный WebApp SDK загружается в head. Клиент передаёт оригинальный `initData`; сервер проверяет Ed25519-подпись Telegram, срок `auth_date` и создаёт HTTP-only сессию. `initDataUnsafe.start_param` используется только для перехода к комнате, не для выдачи доступа. |
| Вход из браузера | Telegram Login подтверждается сервером; согласие на сообщения ботом не запрашивается при входе. |
| WebView | При запуске вызываются `ready` и `expand`, задаются цвета шапки и фона, учитывается Telegram content safe area. Системная кнопка «Назад» ведёт на главный экран или к списку игр и снимает обработчик при уходе со страницы. |
| Игровые действия | Восстановлены HapticFeedback и системный confirm с браузерным запасным вариантом. |
| Веб-клиент Telegram | CSP разрешает Telegram как родительский frame; прежний `X-Frame-Options: SAMEORIGIN` мешал загрузке Mini App в веб-клиенте. Остальные защитные заголовки сохранены. |
| Комната по ссылке | Прямой параметр `startapp=room_CODE` открывает мультиплеер. Сервер проверяет право на комнату по участию; новый игрок входит явно, в уже начатую игру войти нельзя. |
| Повторная игра | Инициатор получает новую комнату со старыми настройками. Недавние соперники видят открытый матч в списке и присоединяются сами. В старую комнату их автоматически не записывают; приглашения и оповещения не отправляются. |
| История | Фильтр «Все / Обычный драфт / Один клуб / Мультиплеер» применяется на сервере до лимита результатов. Мультиплеер показывает никнеймы `@username`, а при их отсутствии — имена игроков из комнаты. ID других пользователей не возвращаются в ответе истории. |
| Webhook бота | Используется `X-Telegram-Bot-Api-Secret-Token`. Рассылка и результаты игры не являются частью механизма повторного матча. |

## Проверка и ограничения

- `tsc --noEmit`, ESLint и сборка Next.js с webpack проходят.
- На тестовой SQLite базе проверены история участника, создание повторной комнаты, её появление у прежнего соперника, присоединение и выборка по трём режимам.
- Нативные WebView Telegram для iOS, Android и веб-клиента требуют ручной проверки на устройстве с реальным Telegram аккаунтом. В автоматических проверках использовались тестовые сессии и локальный сервер.
- Сервер хранит временную связь повторной комнаты с завершённым матчем в `resultJson` комнаты до старта сезона. При будущей миграции схемы её можно выделить в отдельное поле `rematchOf`.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Telegram Web Events](https://core.telegram.org/api/web-events).
