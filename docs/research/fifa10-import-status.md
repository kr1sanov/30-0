# FIFA 10 / РПЛ: проверка перед импортом

## Что содержат предоставленные файлы

Лига: 16 клубов, 16 отдельных составов, 469 игроков. В каждой строке игрока есть FIFAIndex ID, имя латиницей, национальность, номер, возраст, позиция, ОБЩ и ПОТ. Все 469 ID уникальны; сумма строк совпадает с заголовками 16 составов. Исходные английские имена и названия клубов сохранены без перевода в `verified-fifa10-rpl.json` вместе с URL игрока, номером строки и SHA-256 исходных файлов. ОБЩ записан в `rating`, ПОТ — в `primeRating`, без пересчёта. У каждого игрока одно проверенное членство в клубе из предоставленной выгрузки. 26 исходных вариантов позиции приведены к 15 слотам игры с сохранением исходного обозначения в `sourcePosition`. Центральные левый/правый варианты теряют уточнение стороны только в игровом слоте; крайние левый/правый не переставляются.

Это **редакция FIFA 10, а не состав РПЛ сезона 2010**. Список включает «Химки», «Кубань» и «Москву». По [истории клубов РПЛ](https://premierliga.ru/about/) все три вместе выступали в 2009 году; «Москва» и «Химки» после 2009 года не играли в высшей лиге, «Кубань» вернулась в 2011 году. Поэтому в подготовленных данных выбран сезон игры `2009 (FIFA 10)`; файлы не маркируются как подтверждённая лига 2010 года. Рейтинги FIFA 10 не являются оценкой спортивных результатов РПЛ.

## Соответствие проекту

| В источнике | В проекте | Примечание |
| --- | --- | --- |
| FIFAIndex club ID, название клуба | `Club.id`, `nameRu`, `nameEn` | Обе строки содержат исходное английское название. `nameRu` — существующее обязательное поле интерфейса. |
| Редакция FIFA 10 | `Season` | Сезон РПЛ 2009; одна запись и 16 `ClubSeason`. |
| FIFAIndex player ID | `Player.id` | Детерминированный ID сохраняет идентичность для будущих редакций. |
| Имя латиницей | `Player.fullName`, `lastName` | Исходная строка целиком, без догадки о разделении имени и фамилии. |
| Национальность, возраст | `Player.nationality`, `PlayerSeason.age` | Не выведен год рождения из возраста. |
| Позиция | `PlayerSeason.mainPosition` | Исходная позиция остаётся в выгрузке для проверки потерь при нормализации. |
| ОБЩ, ПОТ | `PlayerSeason.rating`, `primeRating` | Именно числовые значения источника. `primeSeason` не выдумывается. |
| Рейтинг клуба АТК/ПОЛ/ЗАЩ | `teamRatings` выгрузки | Схема БД их не хранит, и они не подменяют ОБЩ игрока. |
| «-» контракт/цена/зарплата | Отсутствуют | Значения не придуманы. |

## Проверки и применение

Пользователь разрешил сохранять английские имена как в источнике. Среди 469 записей есть два Guilherme и два Alexey Popov с разными FIFAIndex ID; поэтому уникальность `Player.fullName` заменена обычным индексом. Личность футболиста в базе и правило неповторения в драфте определяются ID, а не строкой имени.

Подготовка и предварительная проверка:

```bash
python3 scripts/prepare-fifa10-rpl.py --input-dir ../upload
node scripts/import-fifa10-rpl.mjs
```

На сервере, после резервирования и синхронизации схемы:

```bash
DATABASE_URL='…' node scripts/import-fifa10-rpl.mjs --apply --backup=./roster-backup-2009.json
```

При применении импортёр сначала проверяет, что нет незавершённых драфтов за последние сутки, и сохраняет резервную копию пяти таблиц составов, а также снимок `GameRun`/`GameSlot`. Затем одной транзакцией заменяет только `Club`, `Season`, `ClubSeason`, `Player`, `PlayerSeason`, проверяя итоговые количества. Пользователи, матчи и история запусков не удаляются. Старые незавершённые драфты, даже более суточной давности, могут ссылаться на прежние ID.

Главная страница больше не содержит ручных чисел 41/1604/2000–2026: существующий `/api/stats` считает сезоны, клубы и игроков с реально существующими составами. Пока база не заменена, отображаются её фактические прежние количества.
