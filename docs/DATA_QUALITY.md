# Качество данных РПЛ

## Текущий статус

Данные в `prisma/seed.ts` и `scripts/data/*.json` пригодны для разработки механики игры, но пока не являются проверенным историческим архивом. Часть фамилий, статистики матчей и сезонных рейтингов была создана генераторами. Поэтому интерфейс и документация не должны называть текущий набор официальным или полным.

## Что считается готовой записью

Для каждой связки «игрок — клуб — сезон» нужны:

- имя игрока в единой русской транскрипции;
- клуб и сезон;
- основная и дополнительные позиции;
- источник состава (`sourceUrl`) и дата проверки (`verifiedAt`);
- отдельно рассчитанный игровой рейтинг с версией методики.

Факт участия в составе и игровой рейтинг — разные сущности. Источник состава подтверждает игрока, клуб и сезон; рейтинг остаётся редакционной игровой оценкой и не должен приписываться РПЛ или другому источнику.

## Правила импорта

1. Импорт не должен создавать имена, составы или статистику для заполнения квоты.
2. Дубли по игроку, клубу и сезону запрещены.
3. Состав с менее чем 18 игроками блокирует строгий аудит до ручной проверки.
4. Исторические переименования клубов нормализуются отдельной таблицей соответствий, без потери исходного названия.
5. Обновление текущего сезона выполняется отдельным импортом и не переписывает проверенные прошлые сезоны.
6. Методика рейтинга версионируется; изменение формулы не изменяет исходные факты.

## Проверка

`npm run data:audit` печатает сводку и первые найденные проблемы. `npm run data:audit:strict` возвращает ненулевой код и предназначен для CI после замены текущих файлов на данные с происхождением.
