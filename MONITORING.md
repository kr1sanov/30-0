# Мониторинг продукта и доставки

Актуализировано 27 октября 2026. Основная пользовательская ссылка — [Telegram Mini App](https://t.me/RPL30_bot?startapp). Эксплуатационный origin указан в [DEPLOYMENT.md](DEPLOYMENT.md).

## Что проверяет health

`GET /api/health` возвращает `status`, `database`, `version`, `responseTime`, `timestamp` и `stats` с количеством клубов, активных канонических игроков, карточек, сезонов, попыток и пользователей. При успехе HTTP 200, при исключении — HTTP 503. Поле `version` сейчас содержит `NODE_ENV`, **не git SHA**. Endpoint не подтверждает WebSocket, Telegram-доставку, корректность каждого состава или установленный commit.

Health не удаляет профили. Очистка вынесена в защищённый POST `/api/maintenance/profiles`, ежедневный workflow и ограниченную проверку текущей подтверждённой личности при входе. Глобальная очистка возвращает фактическое число удалений, обрабатывает ограниченные партии и не запускает рассылки.

При недоступности БД HTTP 503 и обезличенная ошибка. Каждый запрос делает живой `SELECT 1`; шесть счётчиков читаются параллельно и могут отставать на 15 секунд. `revision` содержит SHA сборки из CI либо `unversioned` локально; прежнее поле `version` по-прежнему содержит окружение. Дополнительные короткие кэши главной: 15 секунд для общей базы, 2 секунды для завершённых сезонов.

## Какие сигналы нужны

| Область | Сигнал | Интерпретация |
|---|---|---|
| Доступность | Внешний HTTP, ошибки, время ответа в динамике | Один успешный ответ не является SLO |
| База | Соединение, ошибки запросов, задержки, резервирование | Счётчики не подтверждают качество данных |
| Релиз | Commit, quality/build/upload/verify | Build success не означает установленный релиз |
| Драфт | Старт, сохранение, завершение, причины незавершения | Разделяйте попытки и завершённые сезоны |
| Мультиплеер | Вход/выход, готовность, полнота состава, технические поражения | Важен общий прогон двух участников, а не только открытие лобби |
| Уведомления | Pending/due, аренды, отправка, подтверждение, ошибки | Будущие задачи не считать зависшими; ack не заменяет проверку получения |
| Возвраты | Активность до отправки, opt-out, повторный визит | Возврат пользователя отменяет неактуальную кампанию |
| Данные | Период покрытия, полнота клуб/сезон, позиции, дубли | Разделять seed-кандидаты и фактическую базу |

В админском обзоре есть продуктовые и операционные показатели. Клиентская аналитика находится в `src/lib/metrics.ts`; её наличие в коде не подтверждает приём событий внешним сервисом. Не включайте токены, cookies, контакты и тексты приватных сообщений в диагностику.

## Проверка уведомлений

Путь: событие → outbox → выдача с арендой → транспорт → подтверждение → получение на тестовом устройстве. Сверяйте время ближайшей попытки, настройки пользователя, начало диалога и блокировку бота. Не подтверждайте доставку только по успешному webhook. Workflow очереди может задерживаться по расписанию Actions.

## Приоритеты после аудита

1. Восстановить SSH-загрузку и добавить однозначную идентификацию установленного commit.
2. Подтвердить реальные тестовые доставки и сценарии отмены/повтора.
3. Проверять защищённую очистку и доступность БД независимо от кэшируемых счётчиков.
4. Установить измеряемые базовые значения задержек, ошибок и завершения игровых сценариев; затем задавать целевые пороги.

Не заявляйте конкретный uptime, p95 или прирост удержания без наблюдаемого периода и данных. [Аудит](docs/audits/2026-10-22.md) · [Состояние](PROJECT_STATUS.md).
