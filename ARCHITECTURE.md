# Устройство 30-0

Актуализировано 1 октября 2026 года. Точка входа — `src/app/page.tsx` (Next.js App Router). Состояние драфта хранится в `src/store/gameStore.ts`, сессия пользователя — в `src/store/authStore.ts`. Компоненты экрана находятся в `src/components/game/`; перевод текста — в `src/lib/enTranslations.ts`.

## Игровой цикл

1. На главной странице пользователь выбирает «Обычный драфт» или «Один клуб». Во втором режиме сначала выбирает клуб из `/api/clubs`, где возвращаются только клубы с достаточным пулом игроков и позиций (`src/lib/rplClubSelection.ts`).
2. В настройках выбирает одну из 12 схем (`src/lib/positions.ts`), сложность, режим рейтингов (кроме Prime в «Одном клубе») и тренера. Количество перебросов определяется сложностью.
3. Колесо выдаёт клуб и сезон; список из `/api/club-seasons/[id]/players` предлагает игроков. Правила постановки на позицию и штрафы определены в `src/lib/positions.ts`. Драфт завершается после заполнения 11 мест.
4. Случайный тренер по желанию добавляет +2 к силе состава. `src/lib/simulation.ts` моделирует 30 матчей и таблицу; итог зависит от состава и случайности. Результат сохраняется через API игровых сессий, отображается в профиле и доступен по `/share/[runId]`.

Симуляция и рейтинг не являются официальными результатами РПЛ. Мультиплеерные компоненты остаются в исходном коде, но режим скрыт из публичного интерфейса.

## Данные и API

Prisma-схемы: `prisma/schema.sqlite.prisma` для локальной разработки и `prisma/schema.mysql.prisma` для Jino. Основные сущности: `Club`, `Season`, `ClubSeason`, `Player`, `PlayerSeason`, `User`, `GameRun`, `Achievement`, `AdminCredential`. Смотрите сами схемы для полей и ограничений. Публичные маршруты расположены в `src/app/api/`: `clubs`, `seasons`, `club-seasons/[id]/players`, `formations`, `runs`, `leaderboard`, `health`, `auth`. Часть маршрутов требует сессии; нельзя считать их открытыми только по URL.

Админка `/admin` использует отдельные логин и пароль, cookie-сессию и роли `owner`, `admin`, `moderator`, `viewer` (`src/lib/adminAuth.ts`). Дашборд агрегирует пользователей, игры и записи базы. Раздел составов создаёт сезон, проверяет CSV до записи, импортирует игроков и позволяет ручной ввод; образец CSV доступен в интерфейсе. Псевдоним отображается в игре, исходные имя и фамилия остаются в БД.

Вход игрока через Telegram реализован отдельно от входа администратора. Профиль хранит историю, достижения и приглашения; удаление профиля может быть отменено в течение семи дней. Локальное состояние драфта хранится в браузере. Страницы `/privacy` и `/terms` описывают правила сервиса.

## Развёртывание

`.github/workflows/deploy.yml` запускает линтер, проверку типов и тесты, собирает Next.js standalone, копирует приложение на Jino по SSH, обновляет MySQL и проверяет `/api/health`. `scripts/deploy-production.sh` содержит фактическую процедуру и откат. Инструкции: [DEPLOYMENT.md](DEPLOYMENT.md). Метрики базы в [health](https://30-0.рф/api/health) — текущие, а не константы приложения. Ограничения данных: [docs/DATA_QUALITY.md](docs/DATA_QUALITY.md).
